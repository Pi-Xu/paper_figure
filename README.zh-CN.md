# Academic Figures

[English](README.md) | 简体中文

一个用于学术论文制图的 Codex skill，依据论文内容、研究数据和现有图形开展工作。可用于规划配图、生成数据图和科学插画、修改方法图，以及将图和图注集成到 LaTeX 论文中。

提供研究材料并说明任务后，它会选择合适的绘图方式，保留科学含义，检查实际导出结果，并让独立的子 agent 以第一次看图的读者身份审阅每一版图。

## 快速开始

下载或克隆本仓库。在仓库根目录运行以下命令，可让该技能在你的不同项目中使用：

```bash
mkdir -p ~/.agents/skills
cp -R academic-figures ~/.agents/skills/
```

这是 Codex 官方文档列出的用户级技能目录。如果技能没有出现，重启 Codex。参见[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

在 Codex 中打开研究项目并提出任务，将下面的示例路径换成你的实际文件：

```text
$academic-figures 阅读 paper.tex 并检查 figures/ 中的现有图片。
找出新增图示能明显帮助读者理解的内容，然后生成必要的图片。
采用适中的信息密度，保留方法差异和限定条件，并检查最终导出结果。
```

生成数据图时，请提供相应数据或绘图源码。也可以一并提供参考图、目标图宽或偏好的绘图工具。

如果想先试用而不安装，可以让 Codex 按完整本地路径读取本仓库的 `academic-figures/SKILL.md`，再执行你的任务。

你也可以只请求某一个阶段：

- **规划（Plan）**：提出内容和布局方案，暂不生成图片。
- **生成（Generate）**：依据材料制图，并通过审阅循环改进。
- **评审（Critique）**：对现有图片做一轮独立审阅，给出意见，不修改文件。
- **修改（Refine）**：调整现有图片，保留科学内容，并审阅修改结果。
- **集成（Integrate）**：将选定图片和图注加入指定的 LaTeX 论文。

## 它如何决定画什么

当你要求为整篇论文选择配图时，技能会先检查论文和已有图片。每张候选图都应回答一个明确的读者问题，并提供有用的视觉解释。它会避免重复表达，不固定图的总数，也不要求每节都配一张图。

默认每张图围绕一个核心信息展开，采用适中的信息密度。相关内容可以合并；不同主题或拥挤的布局可能需要拆分。辅助说明可以移至图注，但须保留技术含义和限定条件。你指定的任务范围、图数和信息密度优先于这些默认设置。

| 内容 | 默认绘图方式 |
| --- | --- |
| 数据和定量结果 | 项目已有绘图工具，例如 R 或 Python/Matplotlib |
| 精确方法、公式和结构关系 | 可编辑 SVG、TikZ 或已有的合适工作流 |
| 科学插画和概念性图像 | Codex 内置图像生成和编辑 |

**会使用 GPT Image 2 吗？** 会，在需要插画且内置生图工具可用时使用。[OpenAI 当前官方文档](https://learn.chatgpt.com/docs/image-generation)说明，内置生图使用 `gpt-image-2`。本技能调用该工具，不锁定模型版本，也不要求单独的 API key。数据图和要求精确关系的图采用上表中的代码或矢量方式。如果所需工具不可用，技能会说明限制。

## 指定风格和详细程度

可以提供参考图，并说明想参考的方面：配色、线条、字体、布局或信息密度。技能会结合本论文调整这些视觉选择，不把参考图中的科学内容当作证据。

例如，附上一张参考图后提出：

```text
$academic-figures 为 methods.tex 生成一张方法概览图。
参考附件图片的低饱和度配色和简洁线条，保持适中的信息密度和简短标签。
字体与正文协调，保留不同方法之间的差异，辅助说明放入图注。
目标图宽为 6.5 英寸。
```

没有参考图时，它会遵循论文的字体和尺寸，使用克制的配色及清晰的标签。不强制某一种字体、插画风格或固定布局。

## 图如何被审阅

画图的人清楚这张图想表达什么，所以很难判断第一次看到它的读者能不能一眼看懂，这就是知识的诅咒（curse of knowledge）。因此，技能让一个全新的 Codex 子 agent 审阅每一版图；它没有看过 brief、生图提示词或对话内容。但审阅者也有同样的问题：它懂得比多数读者多，能读懂读者读不懂的内容。所以它必须说明每个结论是怎么得出的，再由 Codex 对照目标读者应有的知识检查这些推理。每一轮分四步：

1. **冷读（cold read）**：审阅者只看缩小到印刷尺寸的图，说明它读到的核心信息、视线最先落在哪里、按什么顺序读图，以及哪些地方看不清或看不懂。对每一个解读，它都要列出依据了图中哪些可见元素，以及用到了哪些惯例或背景知识。
2. **对照审阅**：随后它才读取 brief，比较自己读到的信息和你想表达的信息。它最多给出五条意见，按 blocker、major、minor 分级，每条注明位置和具体改法，最后给出 ACCEPT 或 REVISE 的结论。
3. **推理审查**：Codex 把每个解读的依据与 brief 中列出的目标读者知识对照。凡是依赖清单以外的知识、依赖猜测，或依赖印刷尺寸下看不清的文字的解读，即使审阅者猜对了，也算作这张图没有传达到的地方。这一步只能增加意见、收紧结论。
4. **回应与修改**：Codex 逐条决定是否采纳并写明理由，不会为此牺牲科学准确性，然后修改图片：局部问题在当前图片上编辑，布局问题重新生成。

每一版新图都换一个新的审阅者，所以每一轮都是真正的“第一次看”。审阅者给出 ACCEPT 或默认的三轮用完时，循环结束。如果同一个 blocker 连续两轮没有解决，Codex 会换一种改法或询问你，而不是重复同样的提示词。你会得到审阅过的最佳版本和每一轮的审阅记录。

可以在请求中调整这个循环：

- “最多审阅五轮。”
- “每轮审阅后暂停，让我补充意见。”你的意见优先于审阅者的意见。
- “评审 figures/model.png。”只审阅一轮，不重画。
- “读者是懂回归分析、但不了解结构方程模型的心理学研究者。”这会设定推理审查允许的知识范围；不指定时，Codex 会根据投稿期刊或会议和论文内容推断。

子 agent 依赖 Codex 的 `multi_agent` 功能，可用 `codex features list` 查看是否开启。子 agent 不可用时，技能会用单独的 `codex exec` 进程运行审阅者；两种方式都不可用时，技能会自己审阅，并标注这次审阅不独立。

## 你会得到什么

执行生成任务时，技能会把每一版图片、可编辑源码或准确的生图提示词、相关输入材料引用、审阅依据的 brief（`brief.md`）、每一轮的审阅记录（`review/`）和简短说明保存在一起。矢量工作流包含 PDF 导出和 PNG 预览；生成的插画保留为 PNG。

检查包括科学准确性、最终尺寸下的可读性、数学符号、灰度辨识度和导出缺陷。交付 PDF 时，还会检查从最终 PDF 栅格化得到的预览。论文集成检查在提出集成需求时单独进行，未检查时会明确说明。

仅规划或仅评审的任务，默认在对话中返回结果。
